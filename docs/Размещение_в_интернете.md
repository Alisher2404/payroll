# Как разместить «Зарплату кофейни» в интернете

Подготовлено 22.10.2026 для Alisher2404, Windows 11, GitHub Desktop и Яндекс Браузера.
Это приложение Streamlit. Главный файл: `app.py`. Папка проекта: `C:\Users\1\Documents\Codex\payroll`.
Публикуйте именно payroll, а не всю папку Codex. Ниже каждое пронумерованное действие — отдельный шаг.

## 1. Перед отправкой

1. Откройте папку payroll в Проводнике.
2. Включите «Вид → Показать → Расширения имён файлов».
3. Включите «Вид → Показать → Скрытые элементы».
4. Проверьте наличие `app.py` прямо в payroll.
5. Проверьте наличие `requirements.txt` прямо в payroll.
6. Проверьте наличие `.gitignore` прямо в payroll.
7. Проверьте наличие `.gitattributes` прямо в payroll.
8. Проверьте наличие `.streamlit/config.toml`.
9. Проверьте наличие `assets/DejaVuSans.ttf`.
10. Проверьте наличие `assets/DejaVu-LICENSE.txt`.
11. Уберите свои пароли, токены и ключи из любых самостоятельно добавленных документов.

На компьютере могут оставаться `.venv`, `.venv-cloud`, `data`, `backups`, `qa`, `__pycache__` и `.pytest_cache`: удалять их не нужно. Они исключены из Git. Также исключены рабочие SQLite-файлы, журналы, архивы, `.env`, ключи `.pem`/`.key`, `.streamlit/secrets.toml`. Gitignore не распознаёт произвольный пароль в тексте: не вставляйте реальные секреты в исходники, README, скриншоты или инструкции. `secrets.example.toml` содержит только заглушки — его отправлять можно. Тестовые пароли в tests генерируются случайно и относятся исключительно к временным тестовым базам.

Если репозиторий уже существовал, gitignore не удаляет ранее загруженные секреты из истории. В этой папке при подготовке `.git` не было. Если обнаружите опубликованный пароль, смените его.

## 2. GitHub Desktop: создать репозиторий

1. Откройте GitHub Desktop.
2. Войдите в аккаунт Alisher2404, если приложение просит авторизацию.
3. Выберите **File → Add local repository…**.
4. Нажмите **Choose…**.
5. Выберите папку `C:\Users\1\Documents\Codex\payroll`.
6. Нажмите ссылку **create a repository** в сообщении, что папка ещё не является Git-репозиторием.
7. Укажите **Name: payroll**.
8. Укажите **Local path: C:\Users\1\Documents\Codex**.
9. Проверьте, что итоговый путь — `C:\Users\1\Documents\Codex\payroll`, без второго вложенного payroll.
10. Оставьте **Git ignore: None**, чтобы сохранить подготовленный .gitignore.
11. Оставьте **License: None**, если вы ещё не выбрали лицензию.
12. Оставьте **Initialize this repository with a README** выключенным: README уже есть.
13. Нажмите **Create repository**.
14. Откройте вкладку **History**.
15. Выберите **Initial commit**.
16. Просмотрите список файлов первого коммита.

В списке должны быть исходники, schema.sql, tests, docs, assets, requirements.txt, .github/workflows/cloud-check.yml, .streamlit/config.toml и шаблон Secrets. Не должно быть data, backups, qa, .venv, реальных secrets.toml, файлов баз и журналов. GitHub Desktop может сразу создать Initial commit; тогда Changes будет пустым — проверяйте History. Если изменения остались в Changes, проверьте их там, заполните Summary и нажмите Commit to main. Если видите конфиденциальный файл в коммите — пока не публикуйте репозиторий.

17. Проверьте название ветки в **Current branch**.
18. Если ветка называется master, выберите **Branch → Rename…**.
19. Укажите имя **main** в окне переименования.
20. Подтвердите переименование кнопкой **Rename branch**.
21. Нажмите **Publish repository**.
22. Укажите **Name: payroll**.
23. Оставьте **Keep this code private** включённым.
24. Оставьте **Organization: None**, если это поле показано.
25. Нажмите **Publish repository** в окне публикации.

Если payroll уже существует в аккаунте, выберите другое имя, например payroll-cafe, и используйте его дальше вместо payroll. Если .git уже появился до выполнения инструкции, шаг создания пропускается: после выбора папки нажмите Add repository.

Основа последовательности: [добавление локального репозитория](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop), [первый репозиторий](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop), [публикация](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop).

## 3. Проверить GitHub

1. Выберите в Desktop **Repository → View on GitHub**.
2. Проверьте адрес открывшейшейся страницы: github.com/Alisher2404/payroll.
3. Проверьте метку **Private** рядом с названием репозитория.
4. Проверьте выбранную ветку **main**.
5. Найдите `app.py` в верхнем списке файлов.
6. Откройте `requirements.txt`.
7. Убедитесь, что в нём есть streamlit, pandas, openpyxl, reportlab, pytest, pyarrow, tzdata.
8. Вернитесь к списку файлов репозитория.
9. Проверьте отсутствие data, backups, qa и .venv.
10. Откройте папку `.streamlit`.
11. Проверьте, что там есть config.toml и secrets.example.toml, но нет secrets.toml.
12. Откройте вкладку **Actions**.
13. Выберите запуск **Cloud check**.
14. Дождитесь зелёной отметки задания **linux-python313**.

Это настоящая проверка Linux + Python 3.13: чистая установка библиотек, pip check, все тесты и запуск Streamlit с проверкой HTTP. Пока она не прошла, Linux-совместимость не считается подтверждённой. Если запуск красный, откройте упавший шаг и передайте текст ошибки для исправления. При отключённых Actions включите их в Settings → Actions → General согласно политике своего аккаунта. Для закрытых репозиториев действуют лимиты GitHub Actions вашего тарифа.

## 4. Подготовить вход в приложение

На хостинг не переносится ваша рабочая база, поэтому прежние локальные пароли там не действуют. В облаке будут отдельные учётные записи: owner — администратор, teacher — бухгалтер. Администратор может управлять пользователями и удалять данные; бухгалтер работает с карточками, табелями и начислениями, но не получает административные права.

1. Откройте `.streamlit/secrets.example.toml` в Блокноте.
2. Скопируйте весь текст шаблона.
3. Вставьте его во временную новую вкладку Блокнота.
4. Замените `REPLACE_WITH_YOUR_PRIVATE_PASSWORD` своим паролем администратора от 12 символов.
5. Замените `REPLACE_WITH_ANOTHER_PRIVATE_PASSWORD` другим паролем для преподавателя от 12 символов.
6. Сохраните свои пароли в личном менеджере паролей.

Оставьте кавычки вокруг паролей и логинов. Для простоты используйте латинские буквы и цифры без кавычек и обратной косой черты. Не заменяйте заглушки в файле secrets.example.toml внутри проекта. Временный текст с настоящими паролями нужен только для вставки в Secrets на хостинге; в репозиторий его не отправляйте. Секция demo с enabled=true загружает десять вымышленных сотрудников, графики, табели и доплаты за текущий месяц Душанбе. Налоговые ставки намеренно не выдумываются: настройте их отдельно для учебного расчёта или используйте предварительный расчёт.

## 5. Подключить Streamlit к GitHub

1. Откройте [share.streamlit.io](https://share.streamlit.io/) в Яндекс Браузере.
2. Выберите вход через **GitHub**.
3. Подтвердите аккаунт **Alisher2404** на странице GitHub.
4. Нажмите **Authorize streamlit**, если GitHub запрашивает доступ.
5. Нажмите своё имя пользователя в левом верхнем углу Streamlit.
6. Выберите **Settings**.
7. Откройте **Linked accounts**.
8. В блоке **Source control** нажмите **Connect here** для доступа к закрытым репозиториям.
9. Подтвердите расширение доступа кнопкой **Authorize streamlit** на GitHub.

Если доступ уже предоставлен, повторное подключение не требуется. Не нужно делать репозиторий публичным ради размещения приложения. Официальная инструкция: [подключение GitHub и закрытых репозиториев](https://docs.streamlit.io/deploy/streamlit-community-cloud/get-started/connect-your-github-account).

## 6. Разместить приложение

1. Вернитесь в рабочее пространство Streamlit.
2. Нажмите **Create app**.
3. Выберите **Yup, I have an app.**, если появился такой вопрос.
4. В поле **Repository** выберите **Alisher2404/payroll**.
5. В поле **Branch** выберите **main**.
6. В поле **Main file path** укажите **app.py**.
7. В поле **App URL** укажите **alisher2404-payroll**, если адрес свободен.
8. Нажмите **Advanced settings**.
9. В поле **Python version** выберите **3.13**.
10. В поле **Secrets** вставьте подготовленный текст с вашими паролями.
11. Нажмите **Save**.
12. Нажмите **Deploy**.
13. Дождитесь открытия страницы входа в программу.

Если репозиторий не показан, проверьте доступ к закрытым репозиториям из предыдущего раздела; разрешается вписать Repository вручную. Если App URL занят, добавьте к нему несколько цифр. Не указывайте путь payroll/app.py: при правильном выборе репозитория файл находится в его корне. Установка занимает несколько минут. Названия полей сверены с [инструкцией Streamlit](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

## 7. Проверить и открыть доступ по ссылке

1. Введите логин **owner** в программе.
2. Введите пароль администратора из Secrets.
3. Нажмите «Войти».
4. Откройте раздел «Сотрудники».
5. Проверьте наличие десяти примеров кофейни.
6. Проверьте текущий расчётный месяц в левой панели.
7. Нажмите «Выйти».
8. Проверьте вход под **teacher** с отдельным паролем бухгалтера.
9. Нажмите **Share** в правом верхнем углу страницы приложения.
10. Выберите **Make this app public**.
11. Скопируйте адрес страницы из адресной строки.
12. Откройте этот адрес в окне инкогнито Яндекс Браузера сочетанием **Ctrl+Shift+N**.
13. Проверьте, что открывается вход в зарплатную программу без запроса приглашения Streamlit.
14. Передайте преподавателю ссылку и логин teacher.
15. Передайте преподавателю пароль teacher отдельным личным сообщением.

Публичный доступ Streamlit открывает сайт всем по ссылке, но вход внутри программы остаётся. Репозиторий GitHub при этом остаётся Private. Если пункт публичности оформлен иначе, откройте App settings → Sharing → Who can view this app и выберите This app is public and searchable. См. [официальные настройки общего доступа](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app).

Не раздавайте пароль owner. Бухгалтер teacher — не режим «только просмотр»: он может изменять общие учебные данные. Для независимых баз каждого посетителя нужна отдельная доработка; сейчас все посетители работают с одной базой.

## 8. Обновления программы

1. Сохраните изменённые исходники в локальной папке payroll.
2. Откройте GitHub Desktop.
3. Выберите репозиторий payroll.
4. Откройте **Changes**.
5. Проверьте список изменённых файлов на отсутствие рабочих данных и секретов.
6. Введите описание в **Summary**, например «Исправление отчёта».
7. Нажмите **Commit to main**.
8. Нажмите **Push origin**.
9. Дождитесь зелёного **Cloud check** во вкладке Actions на GitHub.
10. Откройте приложение и проверьте результат обновления.

Streamlit получает изменения из GitHub автоматически. Изменение карточки в браузере меняет SQLite, а не исходники: оно не появляется в GitHub Desktop и не отправляется в GitHub. Обновление библиотек может занять несколько минут.

## 9. Ограничения и перезапуск

Бесплатное приложение засыпает после 12 часов без посетителей. Первый посетитель после сна может увидеть кнопку **Yes, get this app back up!** — она возобновляет запуск. См. [управление приложением и сон](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app).

Локальный диск облака временный. Streamlit не гарантирует сохранность SQLite: файл может пропасть при перезапуске, пересоздании среды или другом обслуживании. Это не означает, что каждый перезапуск обязательно удаляет файл; рассчитывать на его сохранение нельзя. При отсутствии файла программа создаёт новую базу и демо-карточки, а утраченные изменения не восстанавливает. См. [хранение SQLite в Community Cloud](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data).

Для реального кадрового и зарплатного учёта нужна постоянная внешняя база и отдельная настройка доступа. Текущая облачная версия — демонстрация; храните только вымышленные данные. Локальная рабочая база на вашем компьютере остаётся отдельной. Резервную копию можно скачать администратором через «Настройки»; копия на том же временном диске не защищает от его потери. Онлайн-восстановление загруженного SQLite не добавлено.

Чтобы вручную перезапустить:

1. Откройте своё приложение, войдя в Streamlit как владелец.
2. Нажмите **Manage app** в правом нижнем углу.
3. Откройте меню **⋮**.
4. Нажмите **Reboot app**.
5. Подтвердите действие кнопкой **Reboot**.
6. Дождитесь запуска приложения.

После изменения Secrets существующие учётные записи автоматически не перезаписываются: начальные пароли применяются при создании новой базы. Для существующей базы создайте нового пользователя через административные «Настройки»; не рассчитывайте, что смена текста Secrets мгновенно сменит пароль сохранённого пользователя. См. [перезапуск](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/reboot-your-app) и [управление Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/app-settings).

После размещения ваш компьютер и локальный start.bat не нужны для работы облачного сайта: его запускает Streamlit. Отключение вашего компьютера не закрывает ссылку.
