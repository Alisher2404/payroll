# Автоматизированная система расчёта заработной платы

Размещение в интернете: [пошаговая инструкция GitHub + Streamlit Community Cloud](docs/Размещение_в_интернете.md). Главный файл — `app.py`, Python для облака — 3.13. На Linux включается облачный режим: учётные записи берутся из `st.secrets`, без секретов приложение закрывает вход. На Windows сохраняется локальный первый запуск. Для явного выбора режима используется `PAYROLL_MODE=cloud` или `local` (только настройка сервера, не пароль).

Облако предназначено для демонстрации на вымышленных данных: SQLite общая для посетителей, её сохранность на временном диске не гарантируется. При потере файла база создаётся заново с учётными записями из Secrets и десятью примерами кофейни. Рабочая локальная база в GitHub не отправляется. Все новые даты и записи журнала используют Душанбе (UTC+5); прежние временные отметки в существующей базе не переписываются.

Проверка подготовки к облаку: [docs/cloud-validation.md](docs/cloud-validation.md). Linux/Python 3.13 проверяется workflow `Cloud check` в GitHub Actions после публикации; локальный результат не заменяет этот запуск. Файл `requirements-lock.txt` — исторический снимок прежней Windows-среды; хостинг устанавливает только `requirements.txt`.

Локальное приложение для Windows 10/11: Python, Streamlit, SQLite, Pandas. Интерфейс на русском, валюта — сомони (TJS). Для повседневной работы дважды нажмите **«Запустить.vbs»** или ярлык **«Зарплата кофейни»** на рабочем столе. Браузер откроется автоматически, чёрного окна не будет.

**«Остановить.vbs»** или ярлык **«Остановить зарплату»** завершает фоновый сервер. Закрытие вкладки браузера оставляет сервер работающим. После перезагрузки Windows снова запустите ярлык. Повторный запуск не создаёт второй сервер. Если порт занят прежним чёрным окном, закройте его перед запуском ярлыка. Журналы ошибок — `data/server.log` и `data/launcher.log`.

Все сохранённые данные находятся в **data/payroll.sqlite3**. Обновление исходников не сбрасывает базу. При этом ввод в ещё не сохранённой форме не считается записанным: используйте соответствующие кнопки сохранения.

## Установка

На этом компьютере библиотеки уже установлены. На новом компьютере установите Python 3.11 или новее с python.org (компонент Python Launcher) и один раз запустите start.bat для установки. Либо откройте PowerShell в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

Откройте http://127.0.0.1:8501. При первом запуске создайте администратора; готовых паролей нет. После установки библиотек интернет для работы не нужен. Для переноса на компьютер без интернета заранее скачайте зависимости командой `pip download -r requirements.txt -d wheels` на Windows с той же версией Python, затем установите `pip install --no-index --find-links wheels -r requirements.txt`.

## Работа пользователя

1. Войдите в систему. В разделе «Подразделения» заведите подразделения и должности.
2. Добавьте карточки сотрудников: номер предлагается автоматически, но его можно изменить. После сохранения открывается созданная карточка для редактирования. Для следующего человека нажмите «Создать ещё одну карточку». Повторный номер отклоняется понятным сообщением. Укажите график 5/2, 2/2 или ручной, часы смены и первый рабочий день цикла. Для оклада выберите пересчёт по дням или обычным часам. Изменение ставки не переписывает прежние расчёты; перед новым расчётом проверьте применимость ставки к выбранному месяцу.
3. Администратор заполняет «Налоги и удержания». Все числовые поля обязательны; ноль указывается явно. Введите официальный источник и категорию работников. Отметьте проверку только после проверки применимости правил. Периоды не должны пересекаться. Существующие правила можно редактировать, изменения попадут в журнал; старые расчёты сохраняют снимок прежних правил.
4. Выберите месяц слева. Сформируйте табель по графику сотрудника, укажите нерабочие праздничные даты. Это шаблон, который нужно проверить. Отредактируйте каждый день, отпуск, больничный, прогул и часы. Сохраните табель. Даты отпусков/болезни представлены ежедневными кодами. Замена сохранённого табеля шаблоном требует отметки подтверждения.
5. В начислении выберите сотрудника. Проверьте нормы полного месяца по графику и производственному календарю, введите премии, распределённые чаевые, доплаты и удержания. «Сохранить доплаты и удержания» записывает их в БД: они остаются после перезапуска. Обычные часы не должны включать сверхурочные. Отпускные/больничные вводите готовыми суммами по отдельному обоснованному расчёту. Без налоговых правил доступна только сумма начислений до налогов, без суммы к выплате и без окончательного сохранения. При сверхурочных предварительный расчёт также требует настройки множителя.
6. Нажмите «Рассчитать», проверьте расшифровку и сохраните. Изменившиеся исходные данные требуют повторного расчёта. Для исправления сохранённого расчёта включите перерасчёт: предыдущая версия останется в истории, отчёты используют последнюю.
7. В расчётных листках скачайте PDF, откройте его и нажмите Ctrl+P. В отчётах доступны начисления, удержания, подразделения, ФОТ, история с версиями и сравнение месяцев. Экспорт — Excel/PDF. Суммы Excel сохранены точными десятичными строками.
8. Администратор создаёт бухгалтеров и скачивает резервные копии в «Настройках». Журнал показывает последние 300 событий; полная история остаётся в БД.
9. В разделе «Выплаты» регистрируйте реальную выдачу зарплаты: сумму, дату, способ и уникальный номер документа. Допускается частичная выдача; программа показывает остаток, блокирует переплату и повторный документ. Аванс уже вычтен в расчёте — повторно вводить его как выплату остатка не нужно. После выдачи денег перерасчёт блокируется. Ошибочную запись выплаты администратор отменяет с причиной; история сохраняется. Отмена записи в программе не выполняет банковский возврат.

### Редактирование, увольнение и удаление

В «Сотрудниках» выберите человека в поле «Карточка сотрудника», измените поля и нажмите «Сохранить изменения». Бухгалтер может редактировать обычные сведения, но увольнять, восстанавливать и удалять сотрудников вправе только администратор.

**Увольнение:** включите «Увольнение / архив», укажите дату и обязательно заполните «Причина увольнения / основание». Нажмите «Уволить и перенести в архив» либо сохраните изменения. Причина вводится администратором по фактическому основанию; программа не определяет её сама. Если в сохранённом табеле есть работа после этой даты, сначала исправьте табель. При будущей дате увольнения сотрудник появится в архиве после её наступления.

**Архив:** раздел «Архив сотрудников» показывает бывших работников, даты и причины увольнения. Выберите человека — откроются начисления, удержания, авансы, выдача зарплаты, остаток, часы, сверхурочные, отпуска, больничные, прогулы, история выплат и кадровых событий. Статистика охватывает все месяцы и не ограничивается месяцем в боковой панели. Последние версии расчётов суммируются один раз; прежние версии можно показать отдельно. Будущие дни и даты вне периода трудоустройства не включаются в статистику рабочего времени. Детальная история начислений доступна в Excel. Статистика также находится внизу обычной карточки.

**Восстановление:** в архиве нажмите «Открыть карточку для изменения или восстановления», снимите «Увольнение / архив» и сохраните. Прошлая причина остаётся в истории кадровых событий. Это восстановление карточки в списке работающих; для нового отдельного трудового договора заведите новую карточку с новым номером.

**Удаление:** «Удаление ошибочной карточки» подходит для пустой карточки без истории. Для удаления сотрудника вместе с учебными или другими данными администратор раскрывает «Администратор: удалить сотрудника со всей историей», вводит точный табельный номер, причину удаления и подтверждение. Будут удалены карточка, все табели, черновики, расчёты, детализация, выплаты и кадровые события этого сотрудника. Итоги отчётов изменятся. До удаления автоматически создаётся копия всей базы в `data/deletion-backups/`; без успешной копии удаление блокируется. В журнале остаются сведения об удалении, причина и путь копии. Для восстановления используйте эту копию по общей инструкции; восстановление всей базы также вернёт остальные данные к моменту копирования. Сотрудники с историей сами по себе не удаляются и не увольняются при обновлении приложения.

Подразделения и должности можно переименовывать; удалить используемый справочник нельзя.

Карточки, табели и черновики имеют версии для защиты от перезаписи изменений из другого окна. При конфликте обновите страницу и проверьте данные. Налоговые правила изменяет администратор; одновременного редактирования одной записи налоговых правил следует избегать.

## Налоговые правила и границы применения

На 22.10.2026 актуальная применимая редакция законодательства в ходе разработки не подтверждена. Поиск обнаружил официальный [раздел Налогового комитета](https://www.andoz.tj/Legislation/TaxCode) и [текст редакции от 14.05.2025](https://www.andoz.tj/docs/kodex/Tax-Code__14_05_2025-RT_ru.pdf); это не подтверждает действующие правила на расчётную дату. В приложение намеренно не внесены налоговые ставки. Проверка источника, статуса работника и применимости выполняется администратором; программа не проверяет юридическую силу введённой ссылки.

Реализована настраиваемая модель: общая необлагаемая сумма для базы налогов/взносов; отдельный вычет из базы подоходного налога; опциональное вычитание взноса работника; одна или две ступени ставки; отдельный взнос работодателя. Это ограниченный расчётный механизм, а не полная реализация всех специальных режимов РТ. До производственного внедрения необходимо проверить: ставки и категории плательщиков, вычеты и пороги, различия баз, льготы, правила округления, пределы удержаний, алименты, социальные выплаты и оплату сверхурочных/выходных. Изменение правила внутри месяца блокируется: необходим отдельный расчёт по подпериодам вне этой версии программы.

Отпускные, больничные, алименты и специальные выплаты вводятся суммами, без автоматического юридического расчёта. Коэффициент сверхурочных общий, без разделения первых и последующих часов. При различающихся базах/особых категориях необходима доработка движка до применения. Юридически значимые регламентированные формы отчётности не реализованы; экспорт — управленческие ведомости.

## Данные и защита

База: `data/payroll.sqlite3`, создаётся при запуске. SQLite использует внешние ключи и транзакции. Деньги хранятся строками, вычисляются через Decimal с округлением HALF_UP до двух знаков. PBKDF2-SHA256: 600 000 итераций, индивидуальная соль. Доступ администратора к пользователям, налоговым правилам, копиям и журналу проверяется в сервисе. Бухгалтер работает с кадровыми данными, табелями, расчётами и отчётами. Сеанс истекает после 30 минут без действий, выход очищает состояние. Задержка после неверного пароля действует в текущем сеансе браузера.

Сервер слушает только 127.0.0.1. SQLite и копии **не зашифрованы**: ограничьте доступ к папке средствами Windows, используйте отдельную учётную запись и шифрование диска. Не размещайте папку БД в общедоступной сетевой папке. Программа предназначена для локальной работы доверенных пользователей, без защиты от администратора компьютера. Не публикуйте Streamlit в интернет без отдельной защиты.

Резервная копия создаётся через SQLite backup API. Для восстановления: остановите сервер через «Остановить.vbs» (или Ctrl+C при ручном запуске), сделайте копию текущего файла БД, замените `data/payroll.sqlite3` скачанной копией и запустите приложение. Проверьте вход, сотрудников и последний расчёт. Данные копии включают пользователей и журнал. Перед данным обновлением сделана копия в папке `backups`; она не включается в распространяемый архив.

## Демо и проверки

В вашей рабочей базе уже добавлены 10 вымышленных сотрудников кофейни «Зёрна» с номерами CAFE-001…CAFE-010. Прежняя карточка сохранена. Команда: управляющий, старший бариста, три бариста, два кассира, кондитер, уборщик и бухгалтер. Примеры окладов: управляющий 6000 сомони, кондитер 4500, бухгалтер 3000; часовые ставки остальных — учебные суммы. У сменных сотрудников график 2/2 по 12 часов, у остальных — 5/2. Это примеры планирования, а не подтверждение допустимости конкретного режима труда.

Созданы табели октября 2026 и черновики доплат: у старшего бариста премия 300, чаевые 150 и аванс 500; у одного бариста — два дня отпуска. Отпускные остаются нулевыми до отдельного расчёта бухгалтером. Налоговые ставки и окончательные расчёты не добавлены. При вводе реальных данных проверьте все учебные суммы и замените примеры.

В новой установке в «Настройках» нажмите «Добавить примеры кофейни». Повторная загрузка пропускает существующие номера CAFE и не переписывает отредактированные карточки, табели и доплаты. Учебные данные общего назначения из первой версии по-прежнему доступны в `demo/demo.sqlite3`.

Также поставляется готовая `demo/demo.sqlite3`. Для отдельного демонстрационного запуска в новой копии папки проекта создайте папку `data`, скопируйте туда этот файл под именем `payroll.sqlite3`, затем запустите start.bat и создайте собственного администратора. Не заменяйте рабочую базу демонстрационной.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Математические примеры тестов используют **синтетическую фикстуру, не ставки РТ**: доход 10%, работник 2%, работодатель 20%, вычет 100, взнос работника вычитается из базы. Оклад 3000 за 22 дня: начисление 3000, взнос 60, база 2840, налог 284, к выплате 2656; взнос работодателя 600. За 11 дней основная зарплата 1500. Премия 500 и надбавка 200 дают начисление 3700; с авансом 100 и алиментами 50 к выплате 3123.40. Ставка 10.25 × 176 часов = 1804, два сверхурочных часа с множителем 2 = 41.

Архитектура, ER-диаграмма, алгоритм и требования: [docs/architecture.md](docs/architecture.md). Фактические результаты проверок: [docs/test-results.txt](docs/test-results.txt).

Обновление проверено на Windows/Python 3.12.13 и Streamlit 1.66.1: **57 тестов пройдены**. Проверки включают создание/переключение/редактирование/архив/удаление карточек через Streamlit AppTest, понятную ошибку дублирования, предварительный расчёт без налогов, сохранение доплат, расчёт и выплату, все отчёты, защиту от повторной выдачи и переплаты, миграцию старой БД, резервную копию и версии записей. Итог — `docs/test-results-update.txt`; старый отчёт оставлен как история первоначальной проверки. Фоновый сервер проверен реальным запуском и HTTP health-check; повторный запуск использует тот же процесс. Автоматические тесты PDF проверяют создание файла; визуальную пригодность конкретного печатного отчёта проверьте перед передачей сотруднику.
